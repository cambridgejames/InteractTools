# 日志系统

**状态**：现行架构
**最后更新**：2026-10-22

---

## 1. 背景

1. 直播现场出问题时，用户只能描述“连不上”，没有可附带的证据。
2. 单文件日志会无限增长；按天按大小滚动才能长期留在本机。
3. 用户需要一键收集，而不是教他们去 AppData 找文件。

## 2. 结构

- `AppLogger` 同时写内存环形缓冲、控制台和文件。
- 文件：`userData/logs/interact-YYYY-MM-DD.log`。
- winston-daily-rotate-file：按天、单文件 20MB、旧文件压缩、最多 20 个。
- 行格式：`YYYY-MM-DD HH:mm:ss.SSS LEVEL main scope message | detail`。
- 设置 → 数据：等级选择、收集日志；收集生成 `logs/exports/interact-logs-*.zip` 并打开文件夹。

## 3. 关键规则

- 不写 cookie/token/SESSDATA、代理密码、完整带凭据 URL。
- 等级默认 `info`；`debug` 只用于排障，UI 必须提示体积代价。
- 关键位置：启动、配置载入、网络更新、平台连接/断开、工具动作、日志等级、主题应用。
- 渲染进程不直接写文件；需要落盘的信息通过主进程记录。

## 4. 改动时的检查点

- 新模块的错误是否进入 `logger.error/warn`，而不是只 console？
- 日志 detail 是否可能包含用户凭据？
- 轮转上限是否仍为 20 个历史文件？
- 收集 zip 是否包含当前文件与历史压缩文件？

## 5. 已知取舍

| 取舍 | 代价 |
|---|---|
| 历史用 gzip 轮转，收集时再打 zip | 目录里不是逐日 zip，但读取与收集更简单 |
| 主进程单一日志源 | 渲染进程异常需要显式转发 |
