# 动效规范

**状态**：现行
**最后更新**：2026-10-24

---

## 1. 背景

1. 直播工具的操作必须可预测，动画不能延迟主播的下一步。
2. 弹幕是高频流，逐条入场动画会拖慢列表并制造视觉噪音。
3. 不同组件各自写 duration/easing 会导致节奏不一致。
4. 本轮只定义规范，不新增动效实现。

## 2. 原则

- 动效只解释状态变化，不做装饰循环。
- 进入用 ease-out，退出更快；不用线性缓动表达 UI 状态。
- 只动画 `transform` 与 `opacity`；不改 width/height/top/left。
- 可打断：悬停、点击、窗口缩放不能等动画播完才响应。
- 高频操作（弹幕滚动、发送）不加逐条动画。
- 尊重 `prefers-reduced-motion`：关闭位移/缩放，只留淡入淡出。

## 3. 时长与曲线

| 场景 | 时长 | 曲线 |
|---|---|---|
| 控件状态、淡入 | 120ms | `var(--ease-out)` |
| 面板/卡片进入 | 180ms | `var(--ease-out)` |
| 结果弹窗 | 320ms | `var(--ease-out)` |
| 下拉菜单 | 150ms | `var(--ease-out)` |
| 页面切换 | 120ms | `var(--ease-out)` |
| 退出 | 80–120ms | `var(--ease-out)` |

## 4. 禁止

- 弹幕列表逐条入场、无限呼吸/漂浮、自动轮播。
- 用 `scale(0)` 作为进入状态；从 0.96 开始。
- 在滚动容器里给每条消息加 transition。
- 让动画阻塞状态机或倒计时。

## 5. 改动时的检查点

- 是否只改 transform/opacity？
- 是否在 reduced motion 下有降级？
- 是否覆盖 hover / active / focus-visible？
- 是否在低端机用 4x CPU 限速看过掉帧？
