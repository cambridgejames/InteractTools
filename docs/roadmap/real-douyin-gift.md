# 抖音真实礼物样本验证

**状态**：待验证
**关联**：无

---

## 1. 背景

1. 适配器已映射 `WebcastGiftMessage` 的用户、礼物名、数量，协议 fixture 通过。
2. 真实抖音联调只确认过聊天与进场，没有抓到真实礼物样本。
3. 因此不能把“线上礼物一定正常”写成事实。

### 1.1 修改历史

| 日期 | 变更 | 原因 |
|---|---|---|
| 2026-10-22 | 首次定稿 | 真实礼物样本缺失 |

---

## 2. 目标与非目标

**目标**

1. 在一个正在送礼的抖音直播间抓到至少一条真实礼物事件。
2. 确认礼物名、数量、用户名在控制台可见，且不出现发送能力。

**非目标**

- 不做礼物统计、榜单或自动答谢。
- 不要求登录态。

## 3. 设计

- 用现有 `LIVE_DOUYIN_ROOM` 测试入口等待 `kind === 'gift'`。
- 保留原始 payload 的脱敏 fixture，补进 `tests/douyin-protocol.test.ts`。
- 如果服务端要求登录才推礼物，记录为“未验证”并停止，不引入登录。

## 4. 改动清单

| 位置 | 改动 |
|---|---|
| `tests/douyin-live.test.ts` | 增加可选礼物等待与日志 |
| `docs/design/platforms.md` | 验证后把“未验证”改成事实 |

## 5. 风险

| 风险 | 应对 |
|---|---|
| 直播间长时间无礼物 | 换高活跃房间，不伪造事件 |
| 礼物字段与 fixture 不一致 | 以真实 payload 为准修 schema，不猜 |

## 6. 验证方法

1. `LIVE_DOUYIN_ROOM=<room> npm run test -- tests/douyin-live.test.ts`。
2. 人工确认控制台出现“礼物”标签与“送出 X ×N”。
3. 记录房间、时间、结果；未验证就保留“未验证”。
